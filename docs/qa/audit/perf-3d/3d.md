# Step 21 audit — perf-3d: 3D hero runtime on a throttled profile

Date 2026-09-30 · production build (`NEXT_PUBLIC_TEST_HOOKS=1`) on `http://localhost:3200` (perf-only instance) · Windows 11 · Playwright Chromium headless · GPU runs `--use-angle=d3d11` = **NVIDIA GeForce RTX 4060 Laptop (D3D11)** (WEB-QA step 10 used an Intel UHD; the GPU here is stronger, so every CPU-side miss below would be equal or worse on an integrated GPU) · SwiftShader runs are recorded as the software-GL floor only.

Scripts (all `scripts/qa/audit/`): `perf-3d-gl.mjs` (WebGL instrumentation: contexts via WeakRef, draw calls/triangles per rendered frame, GPU-memory estimate), `perf-3d-frames.mjs` (intent → ready, start long tasks, scroll through the whole explode track: rAF intervals, long tasks), `perf-3d-profile.mjs` (V8 CPU profile of the start or of the scroll), `perf-3d-interact.mjs` (hover/click/tap with LoAF + Event Timing, idle and off-screen frames), `perf-3d-leak.mjs` (5 home ↔ /delovi client-side cycles, forced GC; `--bare` = no GL wrapping, control), `perf-3d-retainers.mjs` (heap snapshot + retaining paths of old canvases), `perf-3d-dpr.mjs` (adaptive DPR on a 3× phone), `perf-3d-ext.mjs`. The original `scripts/qa/hero-frames.mjs --base http://localhost:3200 --gpu` was also run 3× (uninstrumented control).

## 3. 3D start (intent → first frame → ready)

| Profile | intent → first GL draw | intent → ready | worst start long task | sum over 50 ms |
|---|---|---|---|---|
| Desktop 1×, cold browser (3 launches) | 426–436 ms | 709–1443 ms | 374 ms (PMREM) | 0–525 ms |

| Mobile 4× (3 runs) | 963–1076 ms | 1492–2707 ms | **765 / 294 / 313 ms** | 527–1603 ms |
| Mobile 6× (3 runs) | 1418–1789 ms | 2544–3758 ms | **897 / 435 / 616 ms** | 1267–2293 ms |

Attribution (V8 profiles, `profile-start-*.txt`): (1) the canvas chunk evaluation, 255–345 ms at 4× (`turbopack … H`, 282 KB gzip); (2) **`PMREMGenerator.fromEquirectangular` → `_applyGGXFilter` → `getUniforms` → `getProgramParameter`: the PMREM blur shader compiles synchronously** — 336 / 344 / 457 ms at **1×** on three fresh browsers, 725–884 ms at 4×; (3) the first real frame after `compileAsync` still blocks 160–190 ms in `getProgramParameter` plus 52–92 ms of `texSubImage2D` (KHR_parallel_shader_compile is available — `perf-3d-ext.mjs`); (4) idle-slice jobs (EdgesGeometry, BVH `computeBoundsTree`) of 60–155 ms each at 4× after ready. Warm browsers (program cache hit) drop (2) to ~77 ms — first-time visitors (ad traffic) always pay it.

What loads when (every run): nothing 3D before intent (no GLB, HDR or three chunk). After intent: high → `car.glb` (3.64 MB, 2.05 MB gzip), mid → `car-lite.glb` (2.63 MB), both → `studio-512.hdr` (410 772 B, **served without compression**), two shadow WebP (14 + 20 KB), canvas chunks 183 + 99 KB gzip, three-mesh-bvh 27 KB (fine pointer only), 4 meshopt workers (stay alive for the session).

## 5. Memory and leak check (`leak-desktop-gpu*.json`, `retainers.*`)

5 cycles home (3D ready → full explode → select turbina → close) → `/delovi` (header link) → back, forced GC ×3 before every measurement:

| After | JS heap | DOM nodes | listeners | contexts created / reachable after GC / live | GPU est. |
|---|---|---|---|---|---|
| home, poster | 5 MB | 1235 | 506 | 0 / 0 / 0 | 0 |
| visit 1 (home, 3D) → /delovi | 14 → 13.3 MB | 1221 → 1365 | 702 → 747 | 2 / 1 / 1 → 2 / 1 / 0 | 62.1 → 0 |
| visit 2 → /delovi | 16.1 → 14.6 | 2317 → 3055 | 902 → 1028 | 3 / 2 / 1 → 3 / 2 / 0 | 62.1 → 0 |
| visit 4 → /delovi | 17.9 → 15.9 | 5114 → 5269 | 1356 → 1374 | 5 / 4 / 1 → 5 / 4 / 0 | 62.1 → 0 |
| final (home) | 18 MB | 6247 | 1528 | 6 / 5 / 1 | 62.1 |

(`--bare` control, no GL wrapping; the instrumented run is the same.) GPU resources are released on unmount (the context is lost, live = 0 off the home page) and geometry backing stores do not accumulate (`Runtime.getHeapUsage` backing storage flat at 11.7 MB — the cached GLB `ArrayBuffer` in `lib/three/assets.ts` is part of it). But **every previous renderer's canvas + WebGL context stays reachable and keeps its whole detached home DOM alive: +1107 DOM nodes, +173 listeners and ≈ +0.7–1 MB JS heap per home visit.** Retaining paths from the heap snapshot: the latest renderer via React Three Fiber's module-level loop state (`… .i .gl (WebGLRenderer) .domElement → canvas`), older ones via a module-level three.js texture `Source` (RG half-float LUT, cache key `1001,1001,0,1006,1006,1,,1030,1016,false,false,false,1,`) used as a WeakMap key → `.texture` `WebGLTexture` → `WebGL2RenderingContext` → `<canvas data-engine="three.js r186">`.

Console: `THREE.Clock: This module has been deprecated. Please use THREE.Timer instead.` once per 3D start (6/6).

## 6. Adaptive DPR (mobile 390 @ 3×, `dpr-mobile.json`, crops `dpr-mobile390x3-*.webp`)

Ends at 1.5 / 1.5 / 1.25 (DPR script) and 1.25 / 1.0 / 1.0 (frames runs, 4×). The step-down reacts to main-thread frame time, which DPR does not change on a CPU-bound frame; not reproducible 3× at the same value, so recorded here only. The mid tier renders without MSAA at ≤ 1.5 by contract (F7.2): after the crossfade the roof and wiper lines are visibly stair-stepped next to the poster (`dpr-mobile390x3-poster.webp` vs `dpr-mobile390x3-canvas-run0.webp`) — intentional trade-off, noted for the visual track.
