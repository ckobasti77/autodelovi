3. Budget / method
- BRIEF 9: mobile Lighthouse lab CLS <= 0.05; D112 budget method = applied throttling -> 0.082 in 3/3 (measurement verifier). Simulated 0.100 also fails.
- Not a localhost artefact: localhost is the best case; preload:false means the font is requested only after CSS + layout, so a cold mobile load paints the fallback first. Only a warm HTTP cache (font fetched on an earlier page) avoids it.
- Precedent: docs/qa/STOREFRONT.md SF-02 (same class on product, CLS 0.068) was P1 and fixed by D127; the generation-page chips were missed. DESIGN-SYSTEM 4.2 "size-adjusted fallbacks (no CLS)" is false for Martian Mono.

4. Suggested-fix review
- "inline-block w-[11ch]": ch = advance of "0", which is 0.873 em in the fallback vs 0.700 em in Martian Mono -> the width still changes 25 %; does not fix.
- "code on its own line": chip width = max(name, code); fallback code line (107 px) is wider than several names -> chips can still re-flow; not guaranteed.
- display:"optional": removes the shift but first-visit users see Arial-caps codes (DESIGN-SYSTEM 4.1 chose Martian for 0/O legibility).
- Better: mono({ adjustFontFallback: false, fallback: [...] }) + own "Martian Mono Fallback" @font-face over 0.6-em system monos (Courier New, Menlo, Droid Sans Mono, DejaVu/Liberation Mono) with size-adjust ~116.7 % and matching ascent/descent -> CLS 0 in the emulation, fixes every mono usage (VIN line too). Optional safety net: engine chips in fixed grid tracks with nowrap.
