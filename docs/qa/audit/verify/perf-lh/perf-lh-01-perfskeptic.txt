## E. Conclusions
1. Contention, not code, explains most of the finder's numbers. The benchmarkIndex filter (>= 3000) is a single snapshot taken before the load, so it does not catch contention during the run. The root hydration task (react-dom, about 3.2 s) runs the same JS on the same data, yet:
   - finder runs kept as "ok": 142–304 ms (median ~230): home 221–291, category 221–236, landing 304, product 255–261, Golf 7 285;
   - quiet runs: 103–254 ms (median ~125).
   TTI also moves: 5.8–6.8 s in the finder runs against 5.5–5.9 s in quiet runs. Category 837, landing 1019, product 551–699, /pretraga 625 and Golf 7 650 are inflated. /pretraga, /kontakt, /za-majstore and /delovi were each run once during the audit peak, so they are not established (audit rule: 3 reproductions).
2. Quiet-run medians against BRIEF §9 (TBT <= 200 ms):
   - over: home 343 (171/353/343) and /upit 262 (297/262/217, J11 inquiry bar 200, 3 of 3 over);
   - marginal: landing 218 (218/167/256).
   - within: category 170 (170/169/487/170); product 143, Golf 7 191, /ponuda 148.
   The step-19 category runs on the same client chunks gave 264/438/352. Across all seven quiet category runs the median is 264, so category sits on the 200 ms line, and every run is over J11's 150 ms.
3. Performance score: not reproduced in quiet runs. Home 89 (bar 85), category 95 (step-19 batch 89), product 94, landing 93. The misses in the 70s come from contended runs. The "simulated TBT 274 ms on the landing" also comes only from runs that the finder's own script labelled contended (bench 1930–2977). Quiet simulated TBT is 20–82 ms.
4. Attribution in quiet runs:
   - react-dom work loop: 99–298 ms of the TBT. This is the root hydration at about 3.2 s plus late tasks at 5.0–5.7 s. It is correct as the main driver.
   - document parse/style/layout: 0–246 ms. It counts only when FCP lands before it, which makes run-to-run TBT bimodal. This is correct.
   - GSAP chunk: 0–4 ms.
   - shell chunk 25dplrt: 0–40 ms (not 51–300 ms).
   The "GSAP ticker frames" do not contribute materially to TBT.
5. /upit has its own cause. The zod-classic + RHF chunk (1uyyf-z7kpx1w.js, 102 KB transfer, 80.5 KB unused) arrives at about 5.95 s and is followed by react-dom tasks of 125–149 ms at 6.0–6.4 s. bootup: react-dom 2.0–2.2 s on /upit against 1.3–1.5 s elsewhere. None of the suggested fixes (ProductGrid islands, lazy header sheets, ConsentBanner, idle TextRevealGlobal) touch it. Candidate fixes: zod/mini or a lazily imported resolver.
6. Method: devtools (applied) throttling is the documented budget method (D112; STOREFRONT SF-12; qa/SEO-ADS), so the finder's method is right. TBT is not a localhost artefact, because hydration cost does not depend on the network, and a fast host (bench ~4000) makes 4x gentler rather than harsher. Under Lighthouse's default Lantern throttling (what PSI uses), TBT passes on every page (20–82 ms), so the field/PSI risk is lower than the applied-throttling numbers suggest.
