## M. Testing strategy

### M1. Vitest (two projects in `vitest.config.ts`)
- **unit** (`jsdom` for DOM code, `node` otherwise): `lib/domain` (pricing — 100 % branches; order/inquiry state machines — every pair of states; `normalizeCode`, `foldForSearch` incl. Cyrillic; quick-order parser; VIN/WMI/model year; PIB/MB with known valid/invalid vectors; phone; Belgrade time across both DST switches; money/VAT), `lib/format`, validation parity fixtures, `lib/excel` (synonyms, number formats, 1250 bytes, delimiters), `lib/seo` (title/description lengths, JSON-LD shapes), feeds (XML/CSV validity, escaping), analytics (event mapping, consent gating, CAPI payload builder with mocked fetch), text reveal (split/restore keeps node identity), `lib/three` (manifest schema vs. taxonomy, tier rules, explode math).
- **convex** (`environment: "edge-runtime"`, `server.deps.inline: ["convex-test"]`, tests in `convex/**/*.test.ts`, `convexTest(schema, import.meta.glob("./**/*.ts"))`, components registered with their test helpers or wrapped behind mockable modules): authz negatives for every function family × role; price-visibility matrix; order submit (re-pricing, stock rules, numbering, invalid payloads, rate limits); state machines through Convex; inquiry → quote → accept → order incl. expiry; carts + merge; quick-order matching; import stage/commit/idempotency/rollback; dispatcher idempotency + retries with fake timers and `t.finishAllScheduledFunctions`; cron local-time logic; seed idempotency; demo removal. ≥ 40 tests by step 06, ~150 by step 17. **As built (step 05):** `convex/{priceVisibility,orders,inquiries,authz,catalog,seed}.test.ts` (65 tests) with the world fixture in `convex/test.setup.ts` (roles: anonymous, 2 customers, blocked, pending/approved A (Majstor 10 %)/approved B (Partner 20 % + 25 % on discs)/suspended mechanics, staff, owner; 5 products covering in stock / low / out / on order / margin guard); pure domain tests in `tests/unit/domain/{pricing,stateMachines,commerce}.test.ts` (pricing + state machines at 100 % statements and branches); `npm run test:convex` runs only the Convex project.

### M2. Playwright
`playwright.config.ts`: `webServer` = build + `next start -p 3100` with `NEXT_PUBLIC_TEST_HOOKS=1`; `baseURL` `http://localhost:3100`; projects `desktop-chromium` (1440×900), `mobile-chromium` (390×844, touch), `reduced-motion`, plus `firefox`/`webkit` for the audit; `reporter: "line"`; traces on retry; screenshots on failure. Data: seeded dev deployment; tests create their own records with e-mails `e2e+<run>-<n>@sklop.test` (flagged `isTest` by `testing.*` helpers, which exist only when `E2E_HELPERS=1` and require `E2E_SECRET`); `testing.cleanup` removes them; admin logs in with `SEED_ADMIN_EMAIL`/`SEED_ADMIN_PASSWORD`. Flow list per step in §N.

**As built (step 12, D122):** instead of public `testing.*` helpers behind `E2E_HELPERS`, the storefront spec (`tests/e2e/storefront.spec.ts`) reads Convex state through **internal** probes in `convex/testing.ts` (`samples`, `orderProbe`, `inquiryProbe`, `backInStockProbe`; QA-only `quotedInquiryToken`) run with the Convex CLI (`node node_modules/convex/bin/main.js run testing:<fn> '<json>'`), so nothing test-only is reachable from the internet. Test orders/inquiries use unique `e2e-<timestamp>@primer.rs` addresses and a unique user agent per run (fresh per-client rate-limit buckets). Screens: `scripts/qa/storefront-shots.mjs` (+ `crop.mjs`, `make-demo-flows.mjs`, `layout-shifts.mjs`). Unit: `tests/unit/lib/{storefront,validation}.test.ts`; Convex: `convex/storefront.test.ts`.

**As built (step 14):** `tests/e2e/mechanics.spec.ts` — register a workshop through `/za-majstore/registracija` → `testing:mechanicProbe` (pending + `mechanic.registered`) → `testing:approveMechanic` (the same helper as the staff button, D136) → „Vaša cena“ on product and search (and never in the server HTML, anonymous or with the mechanic's cookies) → quick order with exact, „više opcija“ (demo equivalents, D135) and not-found lines → one-click inquiry → cart → checkout with company/workshop prefilled and **deferred payment** → `orderProbe` (`deferred`, `mechanic`) → history with the due date; staff approval through `/admin/majstori` as the owner (desktop); axe + reveal on the landing and registration. Fixtures: `testing:quickOrderSamples`. Convex: `convex/mechanics.test.ts` (registration validation, approval authz, quick-order matching incl. readings, stock and rate limit, one-click inquiry, price list, favorites, customer vehicles, deferred payment and credit limit) + price-leak additions in `convex/priceVisibility.test.ts`; unit: `tests/unit/domain/quickOrder.test.ts`, `tests/unit/lib/priceList.test.ts`. Screens: `scripts/qa/mechanic-shots.mjs` → `docs/qa/MECHANICS.md`.

**As built (step 15, D151):** `tests/e2e/admin.spec.ts` (desktop only, owner from `SEED_ADMIN_*`, serial) — dashboard + axe, command palette (Ctrl+K → order number → Enter), bell; create a product in `/admin/proizvodi/novi`, upload `tests/fixtures/part-photo.jpg`, edit the price and reload; order from `testing:createTestOrder` → „Potvrdi“ → „Označi kao poslato“ with courier and tracking number → `orderProbe` (`poslata`, two `order.status_changed`); inquiry from `testing:createTestInquiry` → quote with a free line → send → `adminProbe` (`ponuda_poslata`, `sent`, total); mechanic from `testing:createPendingMechanic` → approve with „Partner“ → `mechanicProfileProbe`; settings Firma save → `adminProbe` → restore. Convex: `convex/admin.test.ts` (staff vs owner, audit entries, transitions with guards and conflicts, edit + add line priced for the mechanic, bulk price/active/category with undo, duplicate, invites, role safety, quote → order by staff, customer block, palette search, 3D part key). Unit: `tests/unit/domain/sla.test.ts`, `tests/unit/domain/company.test.ts` (missing seller data, D156), `tests/unit/lib/adminFormat.test.ts` (incl. the `diffFields` fix, D146). The spec helper `convexRun` parses objects, arrays, numbers and `null` from `convex run`. Screens: `scripts/qa/admin-shots.mjs` (pages, 1440 + 1024) and `scripts/qa/admin-states.mjs` (palette, bell, dialogs, composer, bulk bar, dirty save bar) → `docs/qa/ADMIN.md`.

**As built (step 16, D161–D170):** `tests/e2e/import.spec.ts` (desktop only, serial; purges `IMP-T-/IMP-C-` leftovers before and after via `testing:purgeImportFixtures`, 40 per call) — template download (five sheets, Serbian headers, > 40 categories); `proizvodi-500.xlsx` → header row found below the title block, synonym columns auto-mapped → the check lists the seeded errors and warnings → dry run „490 artikala se upisuje“, „Greške (10)“ → commit → `testing:productBySku` (created inactive, source `import`; the bad-price row absent) → rollback → the product is gone; `proizvodi-1250.csv` → encoding shown as Windows-1250, preview and the stored product name keep č ć ž š đ exactly → commit → rollback; zero console errors. Convex: `convex/imports.test.ts` (authorization, staging with duplicates/unknown category/missing name/negative stock/bad price and a retried chunk, stock/price mode, OEM + manufacturer fallback, commit with price changes/stock movements/import changes/audit/notification/product history, idempotent commit and `commitRow`, failure isolation, rollback incl. „changed after import“, deactivate-missing with the phrase and demo exclusion, image fetch with a stubbed `fetch`, cancel purge, export page). Unit: `tests/unit/import/{parsing,row,workbooks,fixtures}.test.ts` (header synonyms and presets, sr/en numbers and ambiguity, UTF-8/BOM/Windows-1250 and delimiters, image sniffing, fitment text parse + format round-trip, row validation, template sheets, product export → import round-trip, fixture contents). Fixtures: `node scripts/make-import-fixtures.mjs`. Screens: `node scripts/qa/import-flow.mjs <base> <width>` (whole flow + history, record, exports) → `docs/qa/IMPORT.md`.

**As built (step 19, D182–D200):** `tests/e2e/global-setup.ts` writes `.playwright/consent-state.json` (a „rejected“ `sk_consent` cookie) used as `storageState` by every spec, so the cookie banner never covers bottom-of-viewport controls; `playwright.config.ts` passes `REVALIDATE_SECRET` to the web server. `tests/e2e/seo.spec.ts` — JSON-LD parsed out of home/category/landing/product/vehicle HTML (`extractJsonLd`), title ≤ 60 / description ≤ 155 / canonical / robots per route (filters → noindex + clean canonical; cart, checkout, search, sign-in noindex), OG PNG 1200 × 630, robots.txt, sitemap index + every child well-formed (DOMParser) with indexable samples, Merchant XML required fields and prices, Meta CSV header; consent (fresh `storageState`, tag ids via `testing:setTracking` + `/api/revalidate`, Google/Meta hosts stubbed with `page.route`): zero Google/Meta requests before consent + Consent Mode defaults in the dataLayer + axe on the banner, „Odbij sve“ (cookie, nothing loads), granular analytics-only (gtag without Ads/Pixel), „Prihvati sve“ (consent update, GA4 + Ads config, replayed `view_item`, Pixel consent/init/ViewContent, `add_to_cart`, consent log in Convex, reopen from the footer, withdraw → revoke); ads landing (H1, parts, noindex, axe after the reveal settles). Convex: `convex/seo.test.ts` (landing stats + guard + cap + inactive category, feeds without demo and with hidden prices, CAPI payload with mocked `fetch` incl. hashes/dedup id/test code, skip without consent, no row without token, retry after HTTP 500, consent log, sources report + offline conversions with authz, ads landings with validation and audit). Unit: `tests/unit/seo/{metadata,jsonld,sitemapFeeds,landing}.test.ts`, `tests/unit/analytics/analytics.test.ts`. Screens: `node scripts/qa/seo-shots.mjs [base]` → `docs/qa/SEO-ADS.md`. Lighthouse: run with `MSYS_NO_PATHCONV=1` in Git Bash, otherwise `/delovi/…` arguments are rewritten to Windows paths and only `/` is measured.

**As built (step 20, D201–D214):** `tests/e2e/security.spec.ts` — static headers and a fresh nonce per request, every executable `<script>` in the server HTML nonced, zero CSP violations (DOM `securitypolicyviolation` + console) on home with the live 3D hero, category, product, cart, inquiry, sign-in (1440 + 390), GA4/Ads/Pixel after consent (stubbed) incl. the redacted token page, and the admin (dashboard, import, template previews, privacy export download); open-redirect sign-in with `next=/\evil…`. `convex/security.test.ts` — one test per fixed finding (owner seed, self-approval, privacy tools, reset/cart limits, customer role, test-helper gate, link-secret fail-closed, outbox masking, CAPI/click-id/cart retention). `convex/testing.ts` writers and the token reader require `E2E_TEST_HELPERS=1` on the deployment (set on dev; the convex Vitest project sets it in `vitest.config.mts`). Backup drill: `BACKUP_DIR=<extracted export> [BACKUP_STATS=<seed:stats json>] npx vitest run tests/unit/backup` (skipped otherwise; docs/BACKUPS.md §3).

**As built (step 25, D307–D315):** `tests/e2e/rebrand.spec.ts` — the rebrand crawl on the production build. HTTP level (desktop project): 22 fixed routes plus a product, a category × vehicle landing and a model page from the sitemaps, and a 404; for each, the server HTML including the hydration payload must not contain the old name as a word (`/\bsklop\b/i` — „Rasklopi“, „Sklopi“ and „Sklopljeno“ are verbs of the 3D hero), `og:site_name` and `application-name` are „Euromotors Plus“, the title is ≤ 60 characters and ends with „ | Euromotors Plus · OEM Parts“ or „ | Euromotors Plus“ whenever that fits, and the favicon, SVG icon, Apple icon and manifest are linked. The linked icons and the four manifest icons are compared byte for byte with `public/brand/`; `/icons/*` answers 404. JSON-LD: `WebSite` and the business node carry `name` + `alternateName`, the `logo` URL serves the kit file, a product keeps its maker as `brand` and names the shop only as `seller`. Robots, sitemaps, manifest and both feeds are free of the old name and no feed item uses the shop as `g:brand`. The default OG image is 1200 × 630 and the pixels at the plus, the bracket and the ground have the logo colours. Rendered level (both projects): header and footer logos are named, exactly one form is shown, never under its minimum size, target ≥ 44 px, no sideways scroll; visible text, accessible names, tooltips, placeholders and meta content of eight pages are free of the old name; the admin sidebar (or drawer) shows the lockup. A `beforeAll` purges the cached settings row first. Unit: `tests/unit/config/brand.test.tsx` (names, suffix forms, settings defaults, manifest, icon files, logo markup and generated paths against the kit), `tests/unit/seo/metadata.test.ts` (suffix forms at the 60-character boundaries), `tests/unit/email/templates.test.ts` (every template: logo image, alt text, no old name).

### M3. Accessibility, visuals, performance
- axe: `new AxeBuilder({ page }).withTags(["wcag2a","wcag2aa","wcag21a","wcag21aa","wcag22aa"])` on every template → zero serious/critical; keyboard walkthroughs (order, visible focus, dialog trap/return).
- Screenshots: `tests/e2e/screens.spec.ts` at 360/390/768/1024/1280/1440/1920/2560 → `docs/qa/screens/<step>/`; steps open and critique them (docs/qa/*.md).
- Lighthouse: `tests/lighthouse/run.mjs` (lighthouse 13 CLI, `--chrome-path="$CHROME_PATH"`, JSON output, mobile default + `--preset=desktop`, 3 runs → median) against §J11 budgets; results in `.lighthouse/` + summary table; non-zero exit on budget failure.
- Text-reveal check snippet after a full scroll on home, category, product.
- 3D: `3d/scripts/validate.mjs` (size, triangles, draw calls, names vs. manifest vs. taxonomy, coverage, materials, bbox 4.2–4.4 m) + render QA (docs/3d/QA.md) + web QA (docs/3d/WEB-QA.md, frame times under 4× CPU throttle).

### M4. Definition of Done (every change)
`npx tsc --noEmit` · `npm run lint` · relevant unit + Convex tests · e2e for touched flows · screenshots reviewed for UI changes · no console errors · docs/PROGRESS.md entry · commit.
